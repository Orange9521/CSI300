# CSI300 股东回报筛选

筛选同一上市发行人自首次公开上市至截止日，现金分红加已注销股份对应的回购成本，大于累计股权融资的沪深300成分股。所有金额统一为人民币元。

报告首张工作表是**已取得数据摘要**，融资小计仅代表接口返回且可读取的记录；不能冒充上市以来完整股权融资。分红逐笔表保留每10股派息、登记/除息日期和进度，未把来源总股本冒充实际分红基数。回购逐笔表保留源端金额，但未取得注销凭证的金额不计股东回报。

新增`fetch_announcements.py`检索巨潮1990年以来可用的权益分派实施和回购股份注销完成公告，下载PDF、保留原文和校验SHA256。只有公告明确总金额且分红能够与已实施记录对应，或明确注销完成且明确对应回购成本，才加入**已取得的公告金额小计**。模糊匹配、重复经济事件、更正关系不明、无法解析的PDF及分页失败会标记待核实，不猜金额。标题检索不能证明公告没有遗漏，档案也未必覆盖早期上市历史。

## 安装与运行

需要 Python 3.12，使用现有仓库，不需要额外服务或数据库。

```bash
cd /workspace/CSI300
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -q
.venv/bin/python fetch_public.py --output output/csi300_screen.xlsx
.venv/bin/python fetch_announcements.py --output output/csi300_screen.xlsx
```

自动采集分两步：先运行`fetch_public.py`取得官方名单与公共历史记录，再运行`fetch_announcements.py`补充公告核实金额。两者均实际请求公开来源并保留原始响应，不能把HTTP成功认定为历史完整。完整公告检索及下载可能需要十几分钟；`--catalog-cache --workers 8`可复用已检索目录与已有PDF，继续下载缺失文件。缓存重建严格校验分页唯一性，不能将旧的批量查询缓存混入单发行人查询。可使用`--cached`根据当前截止日的完整缓存重新导出；没有缓存会明确报错。

严格账本筛选仍使用`screen.py`：先检查三个公开来源，再读取数据与计算。退出码0表示300个成分股全部具备三项完整历史；退出码2表示名单不可用、输入失败或累计数据缺失，仍导出诊断报告。网络访问失败会写入Excel。TLS验证始终开启。

可提供从中证官网下载的原始xls/xlsx，以及经人工或其他可信程序核验的账本：

```bash
.venv/bin/python screen.py --constituents /path/000300cons.xls \
  --ledger /path/verified_history.json --as-of 2026-10-11 \
  --output output/csi300_screen.xlsx
```

成分股文件必须含`日期`（或`数据日期`）、`成分券代码`（或`证券代码`/`股票代码`）、`成分券名称`（或`证券简称`/`股票名称`）列，也支持官方中英双语列`日期Date`、`成份券代码Constituent Code`、`成份券名称Constituent Name`；要求300个唯一代码、统一日期、不晚于截止日。日期取文件内容，不把下载日充当数据日期。官方当前链接代表最新可下载文件，但不证明没有发布延迟；本地文件无法自动证明为最新名单。对于历史截止日，应自行提供对应日期官方名单。

## 账本格式与核实责任

JSON顶层为`events`和`coverage`。以下为结构示例，不是真实公司数据；不要用于正式结果。

```json
{
  "events": [{
    "code": "000001",
    "event_id": "issuer-2024-final-dividend",
    "kind": "dividend",
    "date": "2025-06-01",
    "amount_cny": "123.45",
    "status": "completed",
    "source": "https://example.org/implementation-announcement",
    "evidence": "合成结构示例：公告页码、实施日期及总金额"
  }],
  "coverage": [{
    "code": "000001",
    "kind": "dividend",
    "first_listing_date": "1991-04-03",
    "through": "2026-10-11",
    "complete": false,
    "scope": "同一发行人全部上市市场，含A/H股；人民币元",
    "source": "https://example.org/reconciled-history"
  }]
}
```

每家公司三类均需独立coverage，只有`complete: true`且截止日期覆盖统计日才汇总。`complete`是导入者的核实声明，程序不能独立证实公告是否遗漏；必须已与历年年报及实施公告核对。确实没有某类事件且完整核实后，才可声明完整并以空事件集合得到0。

事件类别：

- `dividend`：实际支付的现金分红总额，`status: completed`，按支付/实施日入账。排除提案、送股、转增；不把每股分红直接当总额，也不重复计入中期与全年汇总。
- `buyback_cancelled`：仅已注销股份对应的实际回购成本，按注销完成日入账，`status: cancelled`，必须额外提供`cancellation_source`。部分注销只填该部分成本，不能填整个回购计划上限或全部已买入金额。员工持股/股权激励库存股及未注销股份不计。计划或未注销记录可用`status: pending`保存，但不参与累计。
- `equity_financing`：实际完成的发行融资，`status: completed`，额外填`method`：`IPO`、`SEO`（增发，含定向）、`rights`（配股）、`preferred`、`convertible_conversion`、`other_equity`。现金融资统一采用发行募集资金总额（扣费用前）；债券发行时不计融资，仅实际转股对应的本金按转股完成日计一次。发行股份购买资产等非现金股权融资按已核实公允发行对价纳入，明确凭证与估值口径；无法确定则整项融资覆盖不完整。债务融资、二级市场成交、内部送转股均排除。

同一发行人跨市场发行/分红需纳入，首次上市取最早市场日期。外币按事件日期可核实汇率折算为人民币，`evidence`须记录原币金额、汇率及其来源；程序只接受已经核实的人民币金额，不自动猜测汇率。公司合并、主体变更、重新上市等需要明确主体连续性，无法核实就不声明完整。

`event_id`必须标识经济事件而不是公告版本；同一代码/类别/id重复直接报错。同一事件多份公告不能改id重复录入。金额为非负人民币元，最多两位小数。首次IPO募集完成日可能早于首次上市日，仍计入IPO融资；不因此纳入其他上市前私募事件。更正应先修订账本，再运行；不通过负数事件抵扣。来源链接和凭证由导入者负责真实性，程序不自动验证文档内容。

## 输出与计算

自动采集后的Excel包含已取得数据摘要、融资逐笔记录、分红逐笔记录、回购待核实记录、官方公告逐笔核实，以及严格筛选结果、全量与缺失、数据源检查、统计说明、逐笔凭证、覆盖声明。股票代码保留前导0。

- 股东回报 = 累计现金分红 + 累计回购注销。
- 净股东回报 = 股东回报 − 累计股权融资。
- 比率 = 股东回报 / 累计股权融资；融资为0时留空，状态注明未定义。
- 只有三项完整且净股东回报严格大于0才进入结果，按净回报降序。

累计金额以Decimal计算，Excel金额和比率使用十进制文本，避免Excel的15位数值精度限制；如需在Excel中再运算需自行转换并接受精度限制。缺失值为空白，状态给出缺失类别。未完成/未来日期事件不计入截止日金额。筛选反映绝对累计金额，未经通胀、贴现或投资者持有期调整，不构成投资建议。
